# relay

Инструмент, который не даёт ИИ-агентам для программирования тратить квоту подписки
на раздутый контекст. Работает одинаково для любого агента и любой модели: ядро общее,
для каждого агента — тонкий адаптер. Сейчас поддерживаются Claude Code и Codex.

## Зачем

Агент при каждом обращении к модели заново отправляет всю историю чата. Замер логов
владельца за октябрь 2026 года:

- 74% обращений шли с контекстом больше 200 тыс. токенов, средний контекст в больших чатах
  составлял 450–550 тыс.;
- если бы контекст ограничивался 150 тыс., не пришлось бы отправлять заново 66% токенов.

Поэтому главное — вовремя закончить сессию и продолжить в новой, с коротким handoff.

## Что внутри

| Часть | Что делает |
|---|---|
| `relay usage` | Показывает, куда ушли токены: по агентам, по размеру контекста, по сессиям, плюс последние показания квоты |
| Сторож (hooks `SessionStart`, `UserPromptSubmit`, `Stop`) | Когда контекст больше `soft_limit`, предупреждает вас и агента. В конце хода один раз просит агента записать handoff. Когда контекст больше `hard_limit`, просит не начинать новую работу в этой сессии |
| Скилл `relay-handoff` | Как записать handoff и как восстановить работу из него. Формат Agent Skills (`SKILL.md`) |
| `relay statusline` | Строка состояния Claude Code: размер контекста, 5-часовое и недельное окно. Каждое новое показание квоты пишется в журнал |

Сторож никогда не ломает агента: при любой ошибке он молча завершается, а ошибка записывается
в `~/.local/state/relay/errors.log`.

## Установка

Нужен только Python 3.9+ из коробки, зависимостей нет.

```bash
~/Developer/relay/bin/relay install claude --autocompact 350000
```

```bash
~/Developer/relay/bin/relay install codex
```

Codex запускает новые hooks только после того, как вы им доверитесь: откройте Codex и
подтвердите их в `/hooks`.

`--autocompact 350000` — страховка на случай, если предупреждения сторожа проигнорированы.
Claude Code тогда сожмёт историю на 350 тыс. токенов, а не на 97% окна в 1 млн.

Удаление: `relay uninstall claude [--autocompact]`, `relay uninstall codex`. Перед каждой
правкой конфигурации сохраняется резервная копия рядом с файлом (`*.relay-backup-*`).

## Настройка

Встроенные значения можно переопределить в двух файлах. Значения из `<проект>/.relay/config.json`
имеют приоритет над `~/.config/relay/config.json`:

```json
{
  "soft_limit": 150000,
  "hard_limit": 300000,
  "handoff_path": ".relay/handoff.md"
}
```

Если у проекта уже есть свой документ передачи состояния (например, handoff в SDLC Lingo),
укажите его в `handoff_path`. Скилл тоже сначала ищет документ, который задают правила проекта.

## Команды

```bash
relay usage --days 30
```

```bash
relay usage --since 2026-10-01 --agent claude --json
```

```bash
relay context claude <transcript.jsonl>
```

```bash
relay config
```

## Как добавить агента

Агенту нужен адаптер из двух частей:

1. Читатель логов в `relay/transcripts.py`: превращает его журнал в записи `Call` и умеет
   найти размер контекста последнего обращения.
2. Цель установки в `relay/install.py`: куда записать hooks и куда положить ссылку на скилл.

Если у агента нет hooks, скилл `relay-handoff` всё равно работает. Только переключение
на новую сессию тогда запускаете вы.

## Ограничения

- Форматы логов Claude Code и Codex не являются стабильным публичным интерфейсом. Если
  формат изменится, сторож просто перестанет срабатывать, а не сломает агента.
- Ранжирование в `relay usage` построено по соотношению API-цен. Это не доля лимита подписки:
  формулу подписочной квоты провайдеры не публикуют.
- Строку состояния показывает CLI Claude Code. Выводит ли её приложение Claude, не проверялось.
