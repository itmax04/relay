# relay

Инструмент, который не даёт ИИ-агентам для программирования тратить квоту подписки
на раздутый контекст. Работает одинаково для любого агента и любой модели: ядро общее,
для каждого агента — тонкий адаптер. Сейчас поддерживаются Claude Code и Codex.

## Зачем

Агент при каждом обращении к модели заново отправляет всю историю чата. Замер логов
владельца за октябрь 2026 года:

- 74% обращений шли с контекстом больше 200 тыс. токенов, средний контекст в больших чатах
  составлял 450–550 тыс.;
- если бы контекст ограничивался 150 тыс., не пришлось бы отправлять заново 66% токенов.

Поэтому главное — вовремя закончить сессию и продолжить в новой, с коротким handoff.

## Что внутри

| Часть | Что делает |
|---|---|
| `relay usage` | Показывает, куда ушли токены: по агентам, по размеру контекста, по сессиям, плюс последние показания квоты |
| Сторож (hooks `SessionStart`, `UserPromptSubmit`, `Stop`) | Когда контекст больше `soft_limit`, предупреждает вас и агента. В конце хода один раз просит агента записать handoff. Когда контекст больше `hard_limit`, просит не начинать новую работу в этой сессии |
| Скилл `relay-handoff` | Как записать handoff и как восстановить работу из него. Формат Agent Skills (`SKILL.md`) |
| Правило этапов и скилл `relay-plan` | Блок в `~/.claude/CLAUDE.md` и `~/.codex/AGENTS.md`: план этапов с уровнем модели (strong / standard / light), остановка только на смене уровня или выше `soft_limit`, продолжение в новой сессии из handoff. Модели уровней — `relay/catalog.py` (`STAGE_TIERS`) |
| `relay statusline` | Строка состояния Claude Code: размер контекста, 5-часовое и недельное окно. Каждое новое показание квоты пишется в журнал |
| `relay watch` | Советник, работающий параллельно с вашими сессиями: читает живые логи, применяет правила, на триггерах спрашивает LLM, отдаёт всё по локальному API и шлёт уведомления macOS |

Сторож никогда не ломает агента: при любой ошибке он молча завершается, а ошибка записывается
в `~/.local/state/relay/errors.log`.

## Установка

Нужен только Python 3.9+ из коробки, зависимостей нет.

```bash
~/Developer/relay/bin/relay install claude --autocompact 350000
```

```bash
~/Developer/relay/bin/relay install codex
```

Codex запускает новые hooks только после того, как вы им доверитесь: откройте Codex и
подтвердите их в `/hooks`.

`--autocompact 350000` — страховка на случай, если предупреждения сторожа проигнорированы.
Claude Code тогда сожмёт историю на 350 тыс. токенов, а не на 97% окна в 1 млн.

`relay install` также ставит правило этапов (блок между маркерами `relay:plan-rule`) и скилл
`relay-plan`; `--no-rule` — без правила. После смены моделей в `catalog.py` или `soft_limit`
запустите `relay install` ещё раз: блок заменится на месте, остальной текст файла не меняется.

Удаление: `relay uninstall claude [--autocompact]`, `relay uninstall codex`. Перед каждой
правкой конфигурации сохраняется резервная копия рядом с файлом (`*.relay-backup-*`).

## Настройка

Встроенные значения можно переопределить в двух файлах. Значения из `<проект>/.relay/config.json`
имеют приоритет над `~/.config/relay/config.json`:

```json
{
  "soft_limit": 150000,
  "hard_limit": 300000,
  "handoff_path": ".relay/handoff.md"
}
```

Если у проекта уже есть свой документ передачи состояния (например, handoff в SDLC Lingo),
укажите его в `handoff_path`. Скилл тоже сначала ищет документ, который задают правила проекта.

## Советник: `relay watch`

`relay watch` — долгоживущий процесс. Он не тратит токены агентов: только читает их логи
(`~/.claude/projects/**.jsonl`, включая сессии приложения Claude, и `~/.codex/sessions/**.jsonl`).
Переключать модель или начинать новую сессию по-прежнему вы.

```bash
relay watch --once
```

Один проход по активным сессиям (изменённым за `watch_active_hours`, по умолчанию 12 ч): печатает
сессии и советы, ничего не пишет в журнал и не обращается к LLM. Удобно проверить настройку.

```bash
relay watch
```

Постоянный режим: опрос логов раз в 2 с, API на `http://127.0.0.1:8765`. `--no-llm` — только правила,
`--no-notify` — без уведомлений, `--port N` — другой порт.

### Правила (бесплатно, мгновенно)

| Правило | Когда | Совет |
|---|---|---|
| `context` | контекст выше `soft_limit` / `hard_limit`; сессия простаивает дольше жизни кэша | новая сессия из handoff; для заброшенной сессии — не продолжать её |
| `cache` | контекст больше `big_context` (100K), до истечения кэша меньше 5 мин / кэш истёк | отправить сообщение сейчас или начать заново |
| `repeat` | одна и та же команда упала `repeat_failures` (3) раза подряд | остановить агента и посмотреть ошибку самому |
| `large_read` | один ответ инструмента больше `large_read_tokens` (20K) без offset/limit | читать узко: grep, offset/limit |
| `mechanical` | последние `mechanical_run` (10) вызовов только читают/правят файлы, а модель сильная или effort высокий | модель уровнем ниже или effort `medium` |
| `quota` | недельная квота выше `quota_warn` / `quota_high` (75/90 %) или 5-часовое окно выше 90 % | более лёгкая модель или ниже effort |

Время жизни кэша — `cache_ttl` (Claude 3600 с, Codex 600 с). Каждый совет выдаётся один раз; ключи
уже выданных советов хранятся в журнале, поэтому перезапуск не повторяет их.

### LLM-советник

Срабатывает только на триггерах: новый совет правил уровня warn/high и раз в `review_every_calls` (40)
вызовов для сессии с большим контекстом; не чаще раза в 10 мин на сессию и 20 раз в час. Получает
метрики, последний запрос, выдержки ошибок, имена файлов, квоту и каталог моделей. Возвращает
действие, модель и effort только из каталога, причину и уровень важности.

Каталог моделей: Codex — `~/.codex/models_cache.json` (уровень угадывается по описанию, поправить:
`model_tiers` в конфиге); Claude — встроенный список от 2026-11-02, заменяется файлом
`~/.config/relay/claude_models.json` того же вида.

Цепочка провайдеров (`llm.chain`): Groq `openai/gpt-oss-120b` → Groq `openai/gpt-oss-20b` →
Groq `qwen/qwen3.8-27b` → Cloudflare Workers AI `@cf/meta/llama-3.3-70b-instruct-fp8-fast` →
только правила. На 429 берётся следующий ключ того же провайдера (ключ отдыхает `retry-after`),
на 5xx, сетевой ошибке и таймауте провайдер отдыхает `provider_cooldown` (300 с), модель, которой нет
у аккаунта (404 / `model_not_found`), пропускается сутки.

Бесплатной организации Groq из чат-моделей доступны только эти три (проверено 2026-11-03), и их же
использует Lingo. Лимиты Groq считаются на организацию и модель, поэтому ключ relay лучше брать из
отдельной организации Groq. Что видит ключ, покажет `relay advisor check`.
Бесплатные 10 000 нейронов Workers AI в день общие на весь аккаунт Cloudflare, включая Lingo.

### Ключи

relay не хранит ключи в файлах. Источники, по порядку:

| Провайдер | Переменные окружения | Связка ключей macOS |
|---|---|---|
| Groq | `RELAY_GROQ_API_KEYS="k1,k2"` или `RELAY_GROQ_API_KEY` | сервис `relay.groq`, по элементу на ключ; имена элементов — в `llm.groq_keychain_accounts` (по умолчанию `["default"]`) |
| Cloudflare | `RELAY_CF_API_TOKEN` и `RELAY_CF_ACCOUNT_ID` | сервис `relay.cloudflare`, имя элемента — ID аккаунта из `llm.cloudflare_account_id` |

Добавить ключ в связку (команда спросит ключ сама, он не попадёт в историю shell):

```bash
security add-generic-password -s relay.groq -a default -w
```

Второй и следующие ключи Groq — с другими именами, затем перечислите их в `~/.config/relay/config.json`:

```bash
security add-generic-password -s relay.groq -a second -w
```

```json
{"llm": {"groq_keychain_accounts": ["default", "second"], "cloudflare_account_id": "<id>"}}
```

```bash
security add-generic-password -s relay.cloudflare -a <account-id> -w
```

Проверка: по ключу на провайдера уходит один крошечный запрос.

```bash
relay advisor check
```

### Локальный API

Только `127.0.0.1`; запросы с чужим `Host` отклоняются. Для будущего приложения на SwiftUI.

| Запрос | Ответ |
|---|---|
| `GET /api/health` | состояние движка и цепочки LLM |
| `GET /api/sessions`, `GET /api/sessions/<id>` | сессии: контекст, модель, effort, ходы, инструменты, ошибки, простой |
| `GET /api/quota` | последние показания квоты Claude (`quota.jsonl`) и Codex (rate_limits) |
| `GET /api/catalog` | модели по агентам |
| `GET /api/advice?limit=&session=` | советы, новые первыми |
| `POST /api/advice/<id>/outcome` | `{"outcome": "useful" \| "wrong" \| null, "note": "..."}`, тело только JSON |
| `GET /api/config` | файл пользователя, действующие настройки и значения по умолчанию |
| `POST /api/config` | частичные настройки → `~/.config/relay/config.json`, применяются сразу; `null` сбрасывает ключ, `{}` перечитывает ключи из Keychain |
| `GET /api/usage?days=7` | данные `relay usage --json` (кэш 2 мин) |
| `GET /api/agents` | установлены ли хуки, строка состояния и навык у каждого агента |
| `GET /api/events` | поток SSE: события `session`, `advice`, `quota` |

Журнал советов — `~/.local/state/relay/advice.jsonl` (только дозапись; оценки пишутся отдельными
строками `{"type": "outcome"}`). Уведомления macOS — только для уровня high, не чаще раза в час на
сессию и правило.

Что из сессии видит LLM-советник, задаёт `llm.send` (`prompt`, `errors`, `files`, `tools`, по
умолчанию всё `true`); метрики уходят всегда, пока советник включён.

## Приложение для Mac

`app/` — нативное приложение SwiftUI (строка меню + окно), тонкий клиент `relay watch`; советы
показываются в нём и не попадают в чаты агентов. Сборка: `app/scripts/build.sh --open`.
Подробности — [app/README.md](app/README.md).

## Как добавить агента

Агенту нужен адаптер из двух частей:

1. Читатель логов в `relay/transcripts.py`: превращает его журнал в записи `Call` и умеет
   найти размер контекста последнего обращения.
2. Цель установки в `relay/install.py`: куда записать hooks и куда положить ссылку на скилл.

Если у агента нет hooks, скилл `relay-handoff` всё равно работает. Только переключение
на новую сессию тогда запускаете вы.

## Ограничения

- Форматы логов Claude Code и Codex не являются стабильным публичным интерфейсом. Если
  формат изменится, сторож просто перестанет срабатывать, а не сломает агента.
- Ранжирование в `relay usage` построено по соотношению API-цен. Это не доля лимита подписки:
  формулу подписочной квоты провайдеры не публикуют.
- Строку состояния показывает CLI Claude Code. Выводит ли её приложение Claude, не проверялось.
- Советник только советует: MCP и hooks не могут сменить модель или effort работающей сессии.
- Размер ответа инструмента оценивается как символы / 4. Ошибки Codex распознаются по тексту вывода
  (`exit code N`, `Error`, `Traceback`), потому что его инструменты возвращают свободный текст.
- Квота Claude видна, только если установлена строка состояния relay (она пишет `quota.jsonl`).
